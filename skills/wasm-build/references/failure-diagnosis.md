# Failure Diagnosis

Classify failures before changing commands, flags, dependencies, target triples,
or runtime configuration. Every diagnosis should be tied to observable build output, validator output, artifact structure, or repository evidence.

| Failure class | Symptoms | Likely causes | Inspection steps | Recommended next action | Unsafe action to avoid |
|---|---|---|---|---|---|
| missing toolchain | Build command exits with `command not found` or equivalent missing executable output. | Rust, TinyGo, wasi-sdk, Emscripten, Wasmtime, jco, or another route tool is absent. | Inspect the Wasm Build Plan, route README prerequisites, PATH, and command availability. | Report the exact missing prerequisite and ask for explicit approval before any environment or global-toolchain change. | Installing toolchains automatically or replacing the route with unrelated tooling. |
| missing target | Compiler reports an unknown, unavailable, or uninstalled Wasm target such as `wasm32-unknown-unknown` or `wasm32-wasip1`. | The language toolchain exists, but the selected target is not installed or is misspelled. | Inspect the intended environment, selected target, installed target list, and route evidence. | Request approval for the exact target installation, then resume the original build if approved. | Adding random target triples or changing environments to avoid the missing target. |
| wrong WASI preview | Imports, validation output, or runtime errors mention incompatible `wasi_snapshot_preview1` or `wasi:*@0.2.x` namespaces. | A Preview 1 artifact is being used with a Preview 2/component host, or the reverse. | Inspect artifact imports, WIT files, target triple, runtime docs, and BuildPlan environment. | Align the target/interface category with the intended runtime and rebuild after approval. | Mixing Preview 1 modules and components blindly. |
| missing imports | Validator or host reports unresolved imported module/function names. | The selected host/runtime does not provide required imports, or the artifact was built for a different environment. | Inspect `ArtifactStructureReport.imports`, runtime configuration, host bindings, and build output. | Add host binding guidance or choose a compatible route after classifying the missing imports. | Stubbing imports or changing dependencies without understanding the ABI. |
| incorrect exports | Host, plugin runtime, or browser glue cannot find the expected export name or shape. | The artifact exports do not match the selected host/plugin ABI or generated glue expectation. | Inspect `ArtifactStructureReport.exports`, route README expected artifact contract, and runtime docs. | Select the recipe or source annotation that produces the required export contract. | Renaming exports randomly or copying exports from another route. |
| missing memory export where relevant | Plugin host or JS glue reports that exported memory is missing. | The module was generated with settings incompatible with a host that expects exported memory. | Inspect `ArtifactStructureReport.memoryExportPresent`, exports, toolchain flags, and host requirements. | Use only host-documented flags or route-specific recipe changes after approval. | Toggling memory flags until the error disappears. |
| wasm-bindgen compatibility problems | Browser or Node glue fails to load, or generated JS references a different bundler/runtime target. | wasm-bindgen, wasm-pack target, generated glue, and runtime expectations are mismatched or stale. | Inspect generated JS glue, `package.json`, wasm-pack target, and artifact name. | Rebuild with the matching wasm-bindgen/wasm-pack target after approval. | Copying glue from another build or mixing bundler/browser/node outputs. |
| Emscripten versus wasi-sdk confusion | Browser JS glue appears in a WASI route, or WASI imports appear in a browser C/C++ route. | The wrong C/C++ toolchain family was selected for the intended environment. | Inspect build command, Makefile/CMake files, artifact imports, and target-selection table. | Choose Emscripten for browser JS glue or wasi-sdk for WASI according to the BuildPlan. | Combining Emscripten and wasi-sdk outputs in one artifact. |
| WIT/world mismatch | Component build or validation reports unknown world, missing interface, or incompatible generated bindings. | The selected WIT world does not match component metadata or generated bindings. | Inspect `wit/`, `component.json`, jco/cargo-component output, and component WIT validation. | Align the selected world and bindings with the declared component route after approval. | Editing WIT interfaces speculatively without route evidence. |
| component validation failure | `wasm-tools validate` or component tooling rejects a component artifact. | A core module was supplied as a component, metadata is missing, or componentization failed. | Inspect `ArtifactStructureReport.artifactForm`, component metadata, WIT files, and validator output. | Rebuild with the componentization toolchain selected in the BuildPlan. | Treating components as plain core modules or skipping validation. |
| runtime incompatibility | Runtime rejects a valid Wasm artifact because the artifact form or imports are unsupported. | The artifact type does not match the runtime/host capability. | Inspect artifact form, imports, runtime configuration, and target-selection runtime assumptions. | Choose a compatible target/runtime or document the incompatibility. | Repeatedly executing the artifact in the wrong runtime. |
| linker failures | Linker reports undefined symbols, incompatible libraries, relocation errors, or unsupported native objects. | Native dependencies or link flags are incompatible with the selected Wasm target. | Inspect linker output, native dependency list, build scripts, and target-specific recipe notes. | Remove or replace incompatible dependencies with target-supported alternatives after approval. | Broad dependency churn or random linker flag changes. |
| target-incompatible native dependencies | Build output names native libraries, syscalls, threads, sockets, filesystem, or platform APIs unavailable for the target. | The project depends on host-native behavior not supported by browser/WASI/component targets. | Inspect source imports, native build scripts, artifact imports, and runtime permission assumptions. | Document the limitation or refactor behind target-compatible abstractions after approval. | Forcing the target or granting broad runtime permissions without evidence. |
